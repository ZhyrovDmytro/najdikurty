# Scraping strategy

## Provider: JdemeNaTo / CentiSport

The TK Sparta Praha reservation page is generated by Apache Tapestry and includes the full vertical timetable in the first HTML response.

Important page details:

- Day navigation links have ids such as `selectDay-2026-08-04`.
- Sport navigation links have ids such as `selectSport-517795795`.
- Court names are table headers with class `serviceTop`.
- Reservation blocks are `td` elements with classes such as `timetableOccupied`, `timetableClosed`, `timetableLesson`, or `timetableFree`.
- Block times are exposed in the `title`, for example `4:00 PM - 5:00 PM`.
- A CSS class such as `time960` encodes the start minute after midnight.
- `rowSpan` expresses duration in 30-minute units on the current TK Sparta page.

Recommended approach:

1. Use HTTP requests and a cookie jar. JdemeNaTo sets `JSESSIONID` and uses Tapestry links with session ids.
2. Start from the overview URL for the club.
3. If a sport is requested, follow the matching visible sport link, then parse the returned timetable.
4. If a date is requested, follow the matching visible day link, then parse the returned timetable.
5. Normalize the table blocks to provider-independent `CourtAvailability` records.
6. Derive free intervals from the open-day bounds minus blocked intervals.

Use Playwright only when a future provider hides availability behind client-side rendering, anti-bot controls, or interactions that cannot be reproduced with plain HTTP.

For TK Sparta, the public page has limited day navigation. The broader logged-in calendar is available through:

`https://jdemenato.cz/reservation/myportalorganizationcalendar`

Login is a Spring Security form at `/reservation/tk-sparta-praha/login` that posts `j_username` and `j_password` to `/reservation/tk-sparta-praha/j_spring_security_check`. The authenticated direct date URL is:

`/reservation/myportalorganizationcalendar.navigation.daynavigationbar:selectdayinternal/<YYYY-MM-DD>`

Use `TK_SPARTA_EMAIL` and `TK_SPARTA_PASSWORD` environment variables in the API; do not store credentials in source files.

## Provider: SkySportCity / CLUBSPIRE

Padel Prosek uses SkySportCity's CLUBSPIRE reservation system:

`https://rezervace.skysportcity.cz/timeline/day?tabIdx=0&criteriaTimestamp&resetFilter=true#timelineCalendar`

This provider also renders the day timeline in the initial HTML response. The relevant structure is:

- `#hours_head td[id^="time_col_"]` lists hour columns.
- `#activities_halls li.hall` lists court names.
- `#hours_body table.schedule tr[data-row-id]` contains one row per court.
- Hour cells are `td[data-time-id]`.
- Most available/mixed hour cells include `table.table_zoom tr.zoom_items > td` with four 15-minute cells.
- A 15-minute slot is bookable when its cell has `can_book` and contains a reservation link with `reservationStartTime`.
- Full cells are classed as `full`; mixed cells may be `zoom can_book semi_full_3`.

Recommended approach:

1. Convert the requested date to a Europe/Prague local-midnight `criteriaTimestamp`.
2. Fetch `/timeline/day?tabIdx=0&criteriaTimestamp=<timestamp>&resetFilter=true`.
3. Parse court rows and 15-minute bookable cells from the server-rendered table.
4. Merge adjacent 15-minute bookable cells into free intervals per court.
5. Return `slotStepMinutes: 15` to preserve source granularity in the normalized scraper payload.

Note: for tested August 2026 pages, the visual `#day_actual` label can remain on the current day even when the returned reservation links and hidden timestamp reflect the requested date. Use the requested date and `reservationStartTime` values as the reliable source of truth.

## Web booking links

The scraper may preserve source-system granularity, but the product UI intentionally uses 30-minute start steps and 30-minute minimum duration.

Court display names are normalized across all padel providers as `Kurt 1`, `Kurt 2`, etc. Provider-specific court labels are used only to preserve row ordering while parsing and should not leak into the API response.

When a user clicks a matching timeslot:

- TK Sparta opens the JdemeNaTo date-selection URL:
  `https://jdemenato.cz/reservation/myportalorganizationcalendar.navigation.daynavigationbar:selectdayinternal/<YYYY-MM-DD>`
- Padel Prosek opens the SkySportCity day timeline with the Prague local-midnight `criteriaTimestamp`:
  `https://rezervace.skysportcity.cz/timeline/day?...&criteriaTimestamp=<timestamp>#timelineCalendar`
- Playtomic clubs open the Playtomic club page with date and sport params:
  `https://playtomic.com/clubs/<club-slug>?date=<YYYY-MM-DD>&sport=PADEL`
- Head Tenis Centrum opens the iSportSystem padel tab:
  `https://teniscentrum.isportsystem.cz/?op=tab-id-13`
- Padel Neride opens the Reservanto iframe page on the club site:
  `https://padelneride.cz/rezervace/`
- Padel Džus opens the Bookaball booking page:
  `https://padeldzus.bookaball.com/cs/bookings/create?startDate=<YYYY-MM-DD>`
- Padel Powers Smíchov opens the Padelos company page pinned to the Prague club:
  `https://player.padelos.co/company/217?clubIds=216927&locale=cs`

These are date-level deep links. They get the user into the correct booking system and day; the user still completes final court/time selection inside the provider's reservation system.

## Provider: SK Slavia Praha Padel

SK Slavia Praha Padel uses a custom PHP reservation page:

`https://rezervace.padelslavia.cz/`

The public page renders the current-day timetable in the initial HTML response:

- Court headers are in `.tabulka-rezervace table thead th`.
- Time rows are in `.tabulka-rezervace table tbody tr`.
- Cells use `volno` for free and `obsazeno` for occupied.
- `rowspan` expresses multi-slot occupied or free ranges.
- The source table uses 30-minute rows from `08:00` through `22:00`.

Future dates require login at `/cs/prihlaseni`. The login form posts `email` and `password` and redirects to `/cs/rezervace` on success. Once authenticated, date pages are available at:

`/cs/rezervace/index/padel/<YYYY-MM-DD>`

Recommended approach:

1. Fetch `/cs/rezervace` for the current public day.
2. For future days, log in with credentials from environment variables and fetch `/cs/rezervace/index/padel/<YYYY-MM-DD>`.
3. Parse the table while accounting for `rowspan` cells.
4. Normalize court names as `Kurt 1`, `Kurt 2`, `Kurt 3`, `Kurt 4`.
5. Merge adjacent `volno` cells into free intervals.

## Provider: iSportSystem / Head Tenis Centrum

Head Tenis Centrum, Vestec uses iSportSystem:

`https://teniscentrum.isportsystem.cz/?op=tab-id-13`

The rendered page includes a weekly set of padel tables:

- The padel tab is `schema_sport_13`.
- Each `.schemaFullContainer` exposes its date in hidden `data-date` elements.
- Hour headers use two columns per hour, so each court cell is a 30-minute slot.
- Court rows are rendered as `Kurt 1`, `Kurt 2`, `Kurt 3`, and `Kurt 4`; the parser still normalizes names by row order.
- Empty cells with `a.empty` are bookable.
- Cells with `booked`, `old`, or any other class are treated as unavailable.

Direct HTTP requests receive a Cloudflare challenge page. Head Tenis Centrum therefore uses the free `vietaro/cloudflare-bypass-scraper` Apify Actor in forced-stealth mode. One Actor run receives two dated booking URLs concurrently, covering the current and following calendar weeks. The Actor returns rendered Markdown tables; empty Markdown links correspond to `a.empty` bookable half-hour cells, while blank cells are unavailable.

The existing index still reconciles one local date at a time. A module-level 15-minute cache shares the two-page Actor result across all eight date jobs in one worker process, so the 20-minute indexing cadence creates one Actor run rather than eight.

Configuration:

- `APIFY_TOKEN` is required and remains server-side.
- `ISPORTSYSTEM_APIFY_ACTOR_ID` defaults to `vietaro~cloudflare-bypass-scraper`.
- `ISPORTSYSTEM_APIFY_CACHE_TTL_MS` defaults to 15 minutes.
- `ISPORTSYSTEM_APIFY_ACTOR_TIMEOUT_SECS` defaults to 120 seconds.
- `ISPORTSYSTEM_APIFY_AVAILABILITY_TIMEOUT_MS` defaults to 150 seconds for the live API route.

## Provider: Bookaball / Padel Džus

Padel Džus uses Bookaball:

`https://padeldzus.bookaball.com/cs/bookings/create`

The Vue app talks to a JSON API at:

`https://padeldzus.bookaball.com/api`

Important flow:

- Fetch `/cs/bookings/create` first to establish cookies and read the CSRF token.
- Optional login posts JSON to `/api/auth/login` with `email`, `password`, and `remember`.
- Reset/select booking state through `/api/bookings/reset` and `/api/bookings/create`.
- Selecting `STEP_LOCATION` with `location_id: 90` exposes the four padel court ids.
- Selecting `STEP_SIZE` with one court id lets `/api/bookings/times` return per-court start times.

The Bookaball tenant currently accepts 60, 90, and 120 minute durations; it rejects 30 minutes. The scraper therefore fetches the minimum accepted duration, 60 minutes, and exposes `minBookingMinutes: 60` so the UI does not show false 30-minute results for this provider.

## Provider: Padelos / Padel Powers Smíchov

Padel Powers uses Padelos:

`https://player.padelos.co/company/217?clubIds=216927&locale=cs`

The pasted browser URL may contain another `clubIds` value, but the public company metadata identifies:

- company id: `217`
- Prague Smíchov club id: `216927`
- Brno Slatina club id: `216930`

Use `216927` for Prague Smíchov so the scraper does not mix in the Brno location.

The React booking app loads availability through:

`POST https://api.padelos.co/customers/searchByDate`

Important headers:

- `x-clubos-company: 217`
- `x-clubos-club-info: 216927`
- `x-client-route: /company/217?clubIds=216927&locale=cs`
- `x-clubos-channel: CLUBOS-WEB`
- `x-clubos-domain: PADELOSCO`

The request body contains the selected `date` and `sport`, with empty strings for optional filters. The response includes one Prague club object when the headers are correct. Its `availability` array is grouped by exact booking duration (`60`, `90`, `120`) and each slot contains the courts that can be booked for that exact duration.

Recommended approach:

1. Fetch `customers/searchByDate` directly with the Prague club headers.
2. Keep Padelos duration groups as exact `durationAvailability` in the normalized payload.
3. Name courts from sorted known court ids as `Kurt 1`, `Kurt 2`, etc.; do not expose sponsor court names.
4. Expose `minBookingMinutes: 60` because this provider currently offers 60, 90, and 120 minutes.
5. Use exact duration groups in the UI so unsupported durations do not create synthetic slots.

## Provider: Reservanto / Padel Neride

Padel Neride embeds Reservanto on:

`https://padelneride.cz/rezervace/`

The page includes:

`<div class="reservanto-iframe" data-id="22277"></div>`

The Reservanto iframe URL is:

`https://booking.reservanto.cz/form/?id=22277`

Important form values:

- Merchant id: `22277`
- Padel service id: `99005`
- Service label: `Padel tenis - hala léto`

The iframe loads availability by posting the serialized hidden booking form to:

`https://booking.reservanto.cz/PlaceRentalLike/Step2_Calendar`

The response is HTML with an embedded `DailyHorizotalCalendar` model. Its `days` JSON contains locations, three padel sources, and 30-minute availability cells. A slot is bookable when `IsFree`, `CanBeBooked`, and not booked. Source names such as `PADEL hala 1` are used only for ordering; the API normalizes courts as `Kurt 1`, `Kurt 2`, and `Kurt 3`.
