# Search UX and saved searches — 16 November 2026

## Contract

Keep the existing Prague padel product, language support, club information, booking links, and design tokens. Support date ranges, linked club/type selection, and the MultiSport filter. Replace the single unnamed preset with named searches in localStorage. Each saved entry must expose every search parameter, support loading and updating, survive reload, and allow deletion with undo. Preserve the previous preset. Use a persistent desktop sidebar and an accessible mobile panel.

Clicking a saved search applies its filters and immediately runs availability for the entire saved date range. Explicit request parameters prevent stale React state from changing the selected clubs, dates, type, duration, MultiSport setting, or time window. In database mode these queries do not contact booking providers. Names are required, limited to 60 characters, and unique ignoring case and surrounding whitespace. An unavailable storage write leaves the dialog and its input intact. Dates in a saved entry remain unchanged until the user updates it. Running an expired range shifts it into the current booking window, preserves its length where the seven-day horizon allows, and announces the change.

## Design and unslop review

Applied Frontend UI Engineering, followed by a light polish pass using **unslop by Damir Sokolovsky (@heydamir), CC BY 4.0**. The brand, palette, typography family, real club imagery, and product structure stay intact.

Direction: a practical, calm, precise schedule for finding Prague padel times. Quiet controls and a single court-green accent; availability and checked controls carry the color. Saved searches read as compact schedules with dates, times, and club lists.

Audit findings and passes, in order:

1. **Spacing:** dates were separated, the long club list had no nearby submit action, and sidebar parameters needed consistent rows. Put both endpoints together, use 16/24px grouping, and put Search below the club choices as well as above them.
2. **Color:** every selected club tile was green and the page had a radial wash. Keep the checkbox accent, use neutral tile surfaces, and remove the wash on the search workspace.
3. **Icons:** keep the existing Lucide set and real logo; add only functional save, load, delete, and close affordances. Reduce decorative emphasis on the search guidance cards.
4. **Copy:** name the save action, expose local-only persistence, explain date adjustments and storage failures, and use sentence case for quick searches. Remove a duplicate editorial link group while retaining the same links near the news section and footer.
5. **Type:** use 500/600 weights for search controls and headings, tabular saved dates/times, and quiet parameter labels. Keep a page heading available to assistive technology after running a search.
6. **Layout:** add a 280px sticky desktop sidebar; collapse it into a native modal panel on smaller screens. Keep the dates and time window in a predictable two-row form and adapt club columns to available width. Fit the brand at 320px.
7. **Details:** validate empty and duplicate names and short time windows. Keep edits separate from stored parameters until explicitly updated. Preserve custom club selections when deriving court type. Restore calendar focus to the selected day and trigger; allow Escape and keyboard exit. Stop hidden result tooltips from causing horizontal overflow.
8. **Visuals:** use real club and editorial photos already present and actual availability slots as the visual content. No generated decoration, new imagery, or invented product data.
9. **Motion:** retain only existing functional loading and control feedback; honor reduced motion in the search workspace and saved-search dialogs.

Reviewed each search capability: range endpoints, duration and court count, daily time window, court type and manual club selection, MultiSport list filtering, named save/update/delete, quick presets, result sorting, card/compact views, slot selection/sharing controls, freshness controls, and dated booking/detail links.
